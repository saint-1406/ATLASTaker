# Аудит интерфейса и движения (ноябрь 2026, 0.18.1)

Проверено на коде (`src/styles.css`, `src/motion.js`, `src/reader/pager.js`, `src/sidemenu.js`, `src/overlays.js`, `MainActivity.java`) и в браузере на размере телефона 375×812, в тёмной теме с оранжевым акцентом (облик cozy). Android SDK на машине нет, поэтому запуск на устройстве не делался. В приложении работает тот же веб-код внутри WebView.

## Что уже сделано хорошо

- **Система движения есть.** Токены кривых и длительностей (`--ease-*`, `--dur-*`), переходы экранов через View Transitions с направлением (вперёд, назад, вверх). Быстрые нажатия не копятся в очередь: новый переход завершает предыдущий. Есть отклик на нажатие (`.m-press`), появление списков по очереди, FLIP при фильтрации, выключатель «Анимации» и учёт `prefers-reduced-motion`.
- **Листание** следует за пальцем, учитывает скорость. Лист заранее готовится в простое, каждый кадр трогает только transform и opacity.
- **Производительность** продумана (`docs/performance.md`): на телефоне без размытия под панелью вкладок, затемнение меню — отдельный слой, книги раскладываются частями.
- **Safe area**: вне книги окно не заходит под системные панели. В книге отступы панелей и клавиатуры передаются из Java в CSS (`--sys-insets`, `--kb`).

## Осталось

| Важность | Что | Почему не сделано сейчас |
|---|---|---|
| средняя | **Касание посреди перехода теряется.** Проверено: `pointerdown` во время перехода приходит в `<html>`. Добавлено правило `::view-transition { pointer-events: none }` по спецификации, но в этом Chromium касание всё равно не доходило. Похоже, ввод блокируется, пока переход ждёт новый экран (`await openLibrary()`). | Нужно мерить на телефоне. В скрытой панели браузера кадры не идут, и фазы перехода растянуты. Возможный ход: пока идёт переход, нажатие на вкладку пропускает его (`skipTransition()`) и повторяется |
| средняя | **Размер шрифта системы не учитывается.** `setTextZoom(100)` в `MainActivity.java` сделан сознательно: в приложении есть свой масштаб (`fontScale`, 0.75–1.6). | Предложение: при первом запуске брать начальный `fontScale` из системного масштаба Android. Нужна правка на Java и сборка APK |
| низкая | Около 25 размеров шрифта в px (в том числе 9.5, 10.5, 12.5…) и 24 радиуса скругления | Сведение к шкале затронет весь CSS. Лучше делать по экрану за раз со сравнением скриншотов |
| низкая | Глобальное правило reduced motion (`styles.css`, около строки 5160) обнуляет и растворения, хотя их стоит оставить | Нужна проверка всех мест, где анимация несёт смысл |
| низкая | На корневых вкладках («Библиотека», «Заметки») есть «←», хотя внизу панель вкладок | Кнопка ещё закрывает раздел или серию. На компьютере панели вкладок нет, так что это решение по навигации, а не правка стиля |
