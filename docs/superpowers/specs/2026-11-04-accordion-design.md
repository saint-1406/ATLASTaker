# Вставляемый аккордеон в заметках

Статус: согласовано пользователем 4 ноября 2026; выпуск 0.17.2 разрешён в чате.

## Задача

Пользователь уточнил, что нужен отдельный вставляемый блок «аккордеон», а не сворачивание разделов по заголовкам. Блок содержит редактируемое название и произвольный текст заметки, который можно скрывать и раскрывать треугольником. Работает в общем редакторе на компьютере и Android.

## Подходы

1. Стандартные `<details>` и `<summary>` в Markdown. Сохраняют переносимость `.md`, поддерживаются GitHub; в редакторе нужны собственные элементы управления и безопасная обработка при экспорте. Рекомендация разработчика, утверждена пользователем.
2. Собственный синтаксис. Даёт свободу оформления, но требует отдельного формата и преобразований при переносе заметок. Не рекомендуется для существующего Markdown-блокнота.

## Предлагаемое поведение

- Команда «Вставить аккордеон» в палитре и меню редактора; на телефоне также настраиваемая кнопка панели форматирования.
- При выделенном тексте команда помещает его внутрь блока; без выделения создаёт пустой блок с названием «Раздел» (Section в английском интерфейсе).
- Новый блок раскрыт для редактирования. Треугольник скрывает только его содержимое; заголовок остаётся видимым. Управление доступно с клавиатуры и сообщает раскрытое состояние средствам доступности.
- Название можно изменить, содержимое редактируется обычным редактором Markdown. Операция вставки отменяется одним действием Undo.
- Блок хранится как `<details open>`, отдельная строка `<summary>Раздел</summary>`, пустая строка, содержимое, пустая строка, `</details>`. Атрибут `open` хранит состояние раскрытия в самом документе, поэтому оно переживает повторное открытие и синхронизацию.
- Существующие корректные блоки этого формата распознаются. Вложенные блоки учитываются при определении границ; строки внутри блоков кода не становятся аккордеонами. Незавершённая разметка остаётся обычным текстом.
- HTML-экспорт сохраняет интерактивный аккордеон. Текстовый экспорт сохраняет название и содержимое без служебных тегов. Для печати/PDF содержимое раскрывается, чтобы скрытый текст не потерялся на бумаге.
- Разрешается только известная структура аккордеона; произвольный HTML и обработчики событий не исполняются.

## Ограничения и проверки

Сворачивание существующих Markdown-заголовков не входит в эту задачу. Новых зависимостей и отдельного хранилища не требуется. Тесты проверяют вставку/оборачивание, Undo, границы и вложенность, блоки кода, сохранность текста, безопасный экспорт. После реализации — полный набор тестов, сборка и визуальная проверка редактора в узком и широком окне.

## Состояние обновлений Android

Дополнение пользователя перед выпуском: исправить выход из зачёркивания и Enter в пустом чекбоксе. Пробел/Enter на границе перед скрытыми закрывающими `~~` переносятся за них; повторная кнопка зачёркивания на этой границе выводит курсор наружу. Enter в пустом пункте `- [ ] ` сохраняет исходный пункт и создаёт следующий незавершённый пункт. Блоки кода и режим только для чтения не меняются.

В ходе сверки локальный main обновлён с 6695a9d (0.14.2) до 51aa5c9 (0.17.1), совпадающего с релизным тегом. Модуль обновления уже присутствует в src/update.js и Android Updater.java: проверка GitHub Releases, загрузка APK, проверка размера/доступного SHA-256, пакета, версии и подписи, передача системному установщику. Предусмотрен запрос разрешения установки из этого источника. Отдельно создавать дублирующий модуль не нужно.

На этой машине выполнены 215 тестов (все прошли) и node build.mjs (успех). Проверка установки на физическом Android не выполнялась. Первая установка версии с модулем обновления поверх старой версии без модуля выполняется вручную. Требуются совместимая подпись APK, более высокий versionCode и подтверждение системного установщика.
