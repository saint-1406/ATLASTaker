# Сканер документов с OCR

Сканер в ATLAS для Android работает без сети. Снимок листа с камеры или из галереи проходит так: найти края → выровнять перспективу → повернуть → распознать текст (русский, английский и смешанный) → собрать строки и абзацы → отредактировать → сохранить в заметку или TXT. Изображения страниц можно прикрепить к заметке.
Выбор подхода и сравнение с ML Kit, Tesseract и ONNX Runtime описаны в [scanner-ocr-assessment.md](scanner-ocr-assessment.md).

## Где что лежит

| Часть | Файлы |
|---|---|
| Иконка и вход | `src/notesScreen.js` (кнопка в шапке и пункт «Сканировать документ» в меню «+», только если `onScan` передан), `src/app.js` (`openScanner`, `saveScan`, `__atlas.scan`, «Назад»), `src/icons.js` (`scan`) |
| Интерфейс | `src/scanner/scanner.js`: четыре экрана (камера → углы → обработка → результат); `src/scanner/scanner.css` собирается в `dist/scanner.css` и подгружается при первом открытии |
| Камера | `src/scanner/camera.js`: `getUserMedia` (задняя камера, до 4K), `ImageCapture.takePhoto()` в полном разрешении (запасной вариант — кадр видео), вспышка, поиск листа в живом кадре ~3–4 раза в секунду |
| Предобработка | `src/scanner/geometry.js`: поиск листа (Оцу → самая большая светлая область → выпуклая оболочка → четырёхугольник наибольшей площади), гомография, выпрямление (на десктопе), поворот углов |
| Адаптер движка | `src/scanner/engine.js`: `androidEngine` (мост `AtlasAndroid.scan*`, фото частями по 384 КБ, ответы через `window.__atlas.scan`) и `pageEngine` (только выпрямление в странице, без OCR) |
| Сборка текста | `src/scanner/layout.js`: порядок чтения (рекурсивный XY-cut: колонки слева направо, заголовок над ними), строки, абзацы, склейка переносов, исправление похожих букв (`Andrоid` → `Android`, `пспn` → `ncnn`, `AРІ` → `API`, `a также` → `а также`), `12 500 Р` → `12 500 ₽` |
| Заметка | `src/scanner/note.js`: Markdown с заголовком, экранированием `#`/`>` в начале строк и картинками `assets/…` (старый формат заметок не меняется) |
| Мост и Java | `MainActivity.java` (методы `scanInfo/Begin/Append/Process/Cancel/Drop/Close`, адрес `/scan/`, разрешение камеры для WebView, `onTrimMemory`), `Scanner.java` (декодирование с учётом EXIF, не больше 16 Мп; выпрямление одной матрицей `setPolyToPoly` вместе с ручным поворотом; JPEG в кэш; замер времени и памяти), `OcrEngine.java` (загрузка библиотеки, копирование моделей из APK) |
| C++ | `android/app/src/main/cpp/atlas_ocr.{h,cpp}` (PP-OCRv5: осветление тёмных снимков, детекция, определение ориентации 0/90/180/270, распознавание строк параллельно), `atlas_ocr_jni.cpp`, `CMakeLists.txt` |
| Модели | `android/app/src/main/assets/ocr/`: `PP_OCRv5_mobile_det` (2,4 МБ) + `eslav_ppocrv5_rec` (3,9 МБ) + словарь, всего 6,3 МБ; `NOTICE.txt` с лицензиями |
| Библиотеки | `scripts/android-ocr-deps.mjs` скачивает ncnn 20261020 и opencv-mobile 4.12.0 (v34), проверяет их SHA-256 и хеши моделей. Запускается в CI перед Gradle (`release.yml`), папка `cpp/third_party/` не хранится в git |
| Прототип | `scripts/ocr-prototype/`: тот же конвейер на Python с ncnn и OpenCV и генератор тестовых страниц, чтобы проверять точность без телефона |

## Как работает на телефоне

1. «Заметки» → иконка сканера (или «+» → «Сканировать документ»). Сканер открывается поверх экрана заметок, в папке, которая открыта сейчас.
2. Камера. Рамка следует за листом. Справа внизу стопка снятых страниц и кнопка «Готово N». Кнопка галереи открывает системный Photo Picker. Если выбрать несколько фото, они сразу встают в очередь с найденными углами.
3. Правка углов: лупа под пальцем, стрелки с клавиатуры, «Повернуть» на 90°, «Весь кадр». В режиме правки уже снятой страницы есть «Раньше/Позже» и «Убрать страницу».
4. Распознавание начинается сразу после «Оставить», пока снимается следующая страница. Страницы обрабатываются по одной, и памяти нужно примерно на одну страницу, а не на весь скан.
5. Результат: поле названия, редактируемый текст, предупреждения о неуверенных или пустых страницах, «Строки как на бумаге», «Изображения: не прикреплять / выровненные страницы / исходные снимки», «Копировать», «TXT», «Сохранить в заметку». В блоке «Сведения о распознавании» есть отчёт по каждой странице и лицензии компонентов.

«Назад» и Escape ведут на шаг назад; на экране камеры они закрывают сканер (если страницы не сохранены, сначала спрашивается подтверждение). Переходы используют `--ease-emph`, `--dur-route`, `--dur-small` и `--dur-panel` и отключаются при выключенном переключателе «Анимации» и при `prefers-reduced-motion`.

**Защита от ошибок и нехватки памяти.** Снимок декодируется с `inSampleSize` (не больше 16 Мп, при нехватке памяти — 8 Мп). Выпрямленная страница не больше 2400 пикселей по длинной стороне, при нехватке памяти — 1800. На `OutOfMemoryError` и на нехватку памяти в C++ (`bad_alloc`) приходит код `memory`, приложение не падает. При `onTrimMemory` модели выгружаются, если сейчас ничего не распознаётся. Все размеры проверяются до вызова OpenCV: OpenCV-mobile собран без исключений. Если распознавание не удалось, выпрямленная страница всё равно сохраняется. В стопке показываются только маленькие превью (144 пикселя), а не полные страницы.

**Сеть.** Модели входят в APK. Ни JS-, ни Java-, ни C++-код сканера не обращается к сети: это проверяет тест `tests/scanner.test.js`. Страница читает только свои адреса `/scan/…` и `/assets/ocr/NOTICE.txt`. Разрешение `INTERNET` у приложения осталось ради перевода, синхронизации и обновлений, сканер им не пользуется.

## Что проверено здесь

**Тесты.** `node --test tests/*.test.js`: 304 теста проходят (было 280). Новые тесты сканера:
- `scannerGeometry`: поиск листа на синтетических фото, включая тёмные; гомография; выпрямление; поворот углов.
- `scannerLayout`: на настоящих ответах моделей (`tests/fixtures/scanner/*.json`) проверяются колонки, абзацы, переносы и похожие буквы.
- `scanner`: отсутствие сети; модели в APK совпадают с тем, что загружает C++; 519 классов = пустой символ + 517 символов словаря + пробел; Java-методы, которые вызывает страница, существуют; формат заметки.

**Модели на компьютере** (Python ncnn 20261020, fp32, 4 потока; синтетические страницы A4 при 200 dpi; CER — доля ошибочных символов после сборки текста):

| Страница | CER | Найденный поворот |
|---|---|---|
| Русский | 0,0 % | 0° |
| Английский (Times) | 0,0 % | 0° |
| Смешанный ru+en (Calibri) | 1,6 % | 0° |
| Русский, повёрнут на 90° | 0,0 % | 270° ✓ |
| Английский, вверх ногами | 0,0 % | 180° ✓ |
| Смешанный, повёрнут на 270° | 1,6 % | 90° ✓ |
| Русский, тёмный (×0,3, шум) | 0,3 % | 0°, осветлён |
| Русский на столе в перспективе (фото 3000×4000) | 0,3 % | углы найдены с ошибкой ≤ 36 px из 4000 |
| Смешанный, перспектива, тёмный | 1,6 % | осветлён |
| Две колонки | 0,0 % | порядок колонок верный |

Без исправления похожих букв смешанный текст давал 3,6–8 % ошибок. Оставшиеся 1,6 % — это `OcR` в заголовке и `REAДME`: в них нет букв, по которым можно однозначно определить алфавит. Размер входа детектора 960 даёт ту же точность, что и 1280, но вдвое быстрее, поэтому выбран 960. Время на настольном CPU в Python (детекция ~0,4 с, распознавание 0,6–1,2 с на страницу) **не переносится на телефон**: там другой процессор и fp16.

**Сборка без SDK.** C++ компилируется под `aarch64` (zig/clang, `-Wall -Wextra`, без предупреждений) против настоящих заголовков ncnn и opencv-mobile. Java (`MainActivity`, `Scanner`, `OcrEngine`) компилируется `javac --release 17` против `android.jar` API 35 и настоящих jar androidx и Play Services.

**Интерфейс в браузере** (окно 375×812, движок без OCR и тестовый распознаватель): сообщение «Камера не найдена» с переходом в галерею; поиск листа на снимке (углы точнее 3 пикселей экрана); перетаскивание угла; поворот на 90° (рамка остаётся на листе); три страницы из галереи с превью; результат с исправленными `Android`/`Markdown` и склеенным переносом; сохранение в заметку с тремя картинками. Тестовая заметка затем удалена из `.dev-data`.

## Что здесь проверить нельзя

На этой машине нет Android SDK/NDK/adb и телефона. Поэтому **не проверены** такие вещи:
- полная сборка APK с CMake и линковкой ncnn и OpenCV;
- работа `libatlasocr.so` на устройстве: совпадение результатов C++ с прототипом, fp16 на ARM, OpenMP;
- камера в WebView: `getUserMedia`, разрешение `CAMERA`, `ImageCapture.takePhoto` в полном разрешении, вспышка;
- скорость, память и размер APK.

## Что нужно сделать вам

1. **Сборка.** Отправьте ветку в GitHub (или запустите workflow вручную) и скачайте APK из артефактов `android`. Локально в Android Studio: сначала `node scripts/android-ocr-deps.mjs`, потом `gradle -p android assembleRelease`. NDK 27.0.12077973 и CMake 3.22.1 Gradle поставит сам. Обратите внимание на размер APK: ожидается прирост на 12–16 МБ.
2. **Офлайн.** Выключите Wi-Fi и мобильные данные (авиарежим). Откройте «Заметки» → иконку сканера. При первом открытии Android спросит разрешение на камеру.
3. **Точность.** Проверьте такие случаи:
   - русский печатный текст;
   - английский;
   - смешанный (например, техническая документация);
   - лист, повёрнутый на 90° и на 180°;
   - тёмная комната без вспышки, затем со вспышкой (кнопка подсветки вверху справа);
   - документ на 5–10 страниц;
   - пара снимков из галереи.
4. **Бенчмарк.** После каждого скана откройте «Сведения о распознавании» → «Скопировать отчёт» и пришлите текст вместе с моделью телефона. В отчёте для каждой страницы есть размер, найденный поворот, «enhanced», число строк, средняя уверенность, время (decode, flatten, load, recognize: enhance, detect, orient, lines; save, total) и память (native до → пик, Java пик). Первый скан включает загрузку моделей (`load`), поэтому полезно снять 2–3 скана подряд.
5. **Если сломалось:** код ошибки виден в предупреждении на экране результата. Подробности — в `adb logcat -s AtlasOcr`.

## Известные ограничения

- Поиск листа ищет светлую бумагу на более тёмном фоне. Белый лист на белом столе он не найдёт: рамка встанет на весь кадр, углы можно поправить вручную.
- Рукописный текст модель не распознаёт: она обучена на печатном.
- Таблицы читаются по ячейкам слева направо и не превращаются в таблицу Markdown.
- Однострочные абзацы с одинаковыми промежутками неотличимы от текста с двойным интервалом и могут склеиться. Тогда помогает «Строки как на бумаге».
- Свежие версии ncnn предупреждают, что формат 1D-свёрток в этой модели распознавания устарел. Поэтому версия ncnn закреплена (20261020, проверена в прототипе). Перед обновлением ncnn прогоните прототип на новой версии.
- На десктопе (Windows и браузер) иконка сканера скрыта. Включить его можно отдельной задачей: те же модели в ONNX через уже подключённый `onnxruntime-web`, интерфейс общий (`pageEngine` уже умеет выпрямлять страницы).
