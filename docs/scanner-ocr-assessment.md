# Сканер документов с OCR: оценка архитектуры и совместимости

Статус: предложение, код не писался. Дата: 2026-11-10. Версия приложения: 0.18.1.

## 1. Что есть сейчас

**Android (`android/app`)**
- Одна `MainActivity` (Java) с WebView. Страница грузится с `https://<HOST>/assets/…` через `WebViewAssetLoader` — это secure context, поэтому `getUserMedia` в WebView работает.
- Мост JS↔Java: `addJavascriptInterface(new Bridge(), "AtlasAndroid")`. Ответы в страницу идут через `evaluateJavascript("window.__atlas.<event>(…)")`. Тот же приём уже используют диктовка, перевод, обновления и синхронизация, так что OCR встраивается без новых механизмов.
- Фоновые потоки: `ExecutorService io` и `translating`. Для OCR нужен ещё один такой же однопоточный executor.
- Выбор файлов: `onShowFileChooser` уже открывает системный Photo Picker для `accept="image/*"`. Это готовый вход «из галереи».
- Пути отдачи файлов в страницу: `/assets/` и `/incoming/` (`InternalStoragePathHandler`). По этому же образцу добавится `/scan/` для страниц скана. Тогда картинки не гоняются через мост в base64.
- `build.gradle`: AGP 8.7.3, Gradle 8.11.1, Java 17, `minSdk 26 / targetSdk 34 / compileSdk 35`, `abiFilters 'arm64-v8a', 'armeabi-v7a'` (их добавили из-за ML Kit Translate), `jniLibs.useLegacyPackaging true` (нативные библиотеки хранятся в APK сжатыми). **Своего NDK/CMake (`externalNativeBuild`) нет**, нативного кода в проекте нет.
- Разрешения: `RECORD_AUDIO`, `INTERNET`, `REQUEST_INSTALL_PACKAGES`. **`CAMERA` нет.**
- CI (`release.yml`, ubuntu-latest): `npm run build` → `scripts/android-assets.mjs` → `gradle assembleRelease`. NDK на раннере GitHub предустановлен, его нужно только закрепить по версии (`ndkVersion`).
- На этой машине нет Android SDK, NDK, adb и `node` в PATH. Здесь нельзя собрать APK и нельзя ничего запустить на телефоне. Всё нативное проверяется только сборкой в CI и затем на устройстве.

**Веб-слой**
- Картинки заметок уже хранятся как `![alt](assets/<имя>)` через `addImage()` / `api.readAsset`. «Сохранить оригиналы» ложится на этот же путь, **структуры данных не меняются**.
- Экран заметок (`src/notesScreen.js`): шапка с кнопками `tb-btn icon` и FAB «+» с меню. Иконка сканера встаёт в шапку, плюс пункт «Сканировать» в меню FAB.
- Анимации: токены `--ease-*`, `--dur-*`, помощники в `src/motion.js`, переключатель «Анимации», `prefers-reduced-motion`.
- В зависимостях уже есть `@huggingface/transformers` → `onnxruntime-web` 1.31 (WASM). На десктопе он уже работает для перевода. Это важно для варианта OCR на десктопе (см. §6).

## 2. PaddleOCR v5 + ncnn (по DroidOCR)

**Что внутри DroidOCR** (Apache-2.0, последний push 2026-04):
- C++: `ppocrv5_full.cpp` (заголовок — BSD-3, © Tencent: это пример nihui из ncnn), JNI-обёртка `droidocr_jni_full.cpp`, CMake. Зависимости: **ncnn** (`ncnn-20250916-android-vulkan`) и **opencv-mobile 4.12** (только `core` + `imgproc`). Статические библиотеки в репозиторий не закоммичены, их скачивают скриптами.
- Модели (формат ncnn, fp16):

  | файл | размер |
  |---|---|
  | `PP_OCRv5_mobile_det.ncnn.bin/.param` (детектор DBNet) | 2,36 МБ |
  | `eslav_ppocrv5_rec.ncnn.bin/.param` (распознавание, East-Slavic) | 3,92 МБ |
  | `ppocrv5_eslav_dict.txt` | 1,6 КБ |
  | **итого** | **≈ 6,3 МБ** |

- Конвейер: детектор с длинной стороной `target_size` (640 по умолчанию) → боксы `minAreaRect` → вырезка строки `warpPerspective` → распознавание CTC. **Модели ориентации (cls) нет**: вертикальные строки обрабатываются эвристикой, перевёрнутая на 180° страница не определяется.
- В DroidOCR включены Vulkan и fp16. Распознавание идёт в 1 поток.

**Языки.** Модель `eslav_PP-OCRv5_mobile_rec` (Apache-2.0, PaddlePaddle на Hugging Face). Её словарь содержит **полную латиницу + русский, украинский и белорусский алфавиты** (А–Я, Ё, Ґ, Є, І, Ї, Ў), цифры, знаки, № и ₽. То есть **русский, английский и смешанный текст распознаются одной моделью, без переключения языка**. На своём датасете у неё 81,6 % точности *по строке целиком* (строка с одной ошибкой считается неверной). Посимвольная точность заметно выше, но на наших документах её надо мерить. Известный риск — путаница омоглифов (А/A, С/C, Р/P, о/o, х/x). Его снимет постобработка: слово приводится к одному алфавиту по большинству букв.

**Скорость и память (оценка, не измерено).**
- Детектор mobile при 960 px на среднем ARM64 (Cortex-A76, 4 потока): ~150–400 мс.
- Распознавание: ~5–20 мс на строку. Страница из 30–50 строк — **≈ 0,5–1,5 с на CPU**.
- Память: сети ~30–60 МБ. Основной расход — картинка: 12 Мп RGBA ≈ 48 МБ. Поэтому кадр ограничивается ~3000 px по длинной стороне.
- Реальные цифры даст только бенчмарк на телефоне (§8).

**Рост APK (оценка).**
- ncnn, только CPU, статически, с `--gc-sections`: ~1,5–3 МБ на ABI.
- opencv-mobile `core+imgproc`: ~1–2 МБ на ABI.
- Модели: 6,3 МБ (одна копия на все ABI, fp16 почти не сжимается).
- **Итого ≈ +12–16 МБ** на два ABI.
- Vulkan-сборка ncnn тянет glslang и добавила бы ещё несколько МБ на ABI. На документах выигрыш от GPU небольшой, а драйверы Vulkan у части телефонов нестабильны. Предлагаю **CPU-сборку без Vulkan**.

## 5. Рекомендация

**PaddleOCR v5 (det mobile + eslav rec) на ncnn, CPU, через JNI в существующем Android-приложении. Предобработку делает OpenCV-mobile. UI, камера, сборка текста и экспорт живут в веб-слое ATLAS.**

```
JS (src/scanner/…)                        Java (MainActivity.Bridge)          C++ (libatlasocr.so)
──────────────────────────────────        ──────────────────────────          ───────────────────
camera.js   getUserMedia + ImageCapture ─▶ scanAddPage(fileId)  ── executor ─▶ decode (Bitmap, inSampleSize ≤3000px)
            или галерея / системная камера  scanDetectEdges(id)               findDocumentQuad (Canny+contours+approxPoly)
review.js   рамка, ручная правка углов ◀─── window.__atlas.scan(event)        warpPerspective, поворот 0/90/180/270
ocr.js      адаптер (Android / desktop / заглушка) ─ scanRecognize(id) ─────▶ PP-OCRv5 det → rec → [{box, text, score}]
layout.js   порядок чтения, строки, абзацы, омоглифы  (чистый JS, тесты в node --test)
result.js   редактируемый предпросмотр → заметка / TXT / + оригиналы через addImage()
```

Ключевые решения:
1. **Камера в WebView** (`getUserMedia` + `ImageCapture.takePhoto()` для полного разрешения). Видоискатель, рамка документа и переходы рисуются в стиле ATLAS, с токенами `--ease-*`/`--dur-*` и учётом reduced-motion. Нужно добавить `CAMERA` в манифест и обработать `onPermissionRequest` (как сейчас с микрофоном). **Запасные пути**: Photo Picker (уже есть) и системная камера (`ACTION_IMAGE_CAPTURE`), если WebView не отдаёт полное разрешение.
2. **Картинки не идут через мост в base64.** Страницы лежат в `cacheDir/scan/`, страница получает их по `https://<HOST>/scan/<id>.jpg`. Через мост передаются только id и JSON с результатом.
3. **Поворот без отдельной модели**: страница выпрямляется по найденному четырёхугольнику, затем 0° и 180° (90°/270° — по пропорциям боксов) проверяются по средней уверенности распознавания на нескольких строках. Если это окажется ненадёжным, можно добавить `PP-LCNet_x0_25_textline_ori` (~1 МБ, Apache-2.0).
4. **Защита памяти**: декодирование с `inSampleSize`, потолок ~3000 px, страницы обрабатываются по одной, сети освобождаются в `onTrimMemory`/`onLowMemory`, на `OutOfMemoryError` и ошибки JNI возвращается понятный код ошибки, а не падение. Лимит страниц в одном скане ~30.
5. **Без сети**: модели в `assets/ocr/` внутри APK, код сканера не делает сетевых запросов. CSP страницы и так не пускает лишнее. Добавлю тест, который проверяет, что в `src/scanner/` нет `fetch`/`XMLHttpRequest`/`WebSocket` на внешние адреса.
6. **Сборка**: `externalNativeBuild { cmake }` + `ndkVersion` в `build.gradle`. ncnn (CPU-сборка `ncnn-YYYYMMDD-android.zip`) и opencv-mobile скачиваются в CI **с проверкой SHA-256** и кэшируются. Модели (6,3 МБ) — в репозиторий, тоже с хешами. ABI те же: `arm64-v8a`, `armeabi-v7a`.
7. **Ничего лишнего не трогаю**: навигация, хранилище, формат заметок — без изменений. Сканер открывается как оверлей поверх экрана заметок, кнопка «Назад» закрывает его через существующий `window.__atlas.back`.

## 6. Десктоп (вопрос к вам)

ATLAS работает и на Windows (Node-сервер + браузер). Варианты:
- **A (предлагаю для первого этапа):** на десктопе иконка сканера скрыта, сканер только на Android.
- **B (второй этап):** на десктопе работает ввод «из файла» (и веб-камера). OCR — те же PP-OCRv5 в ONNX через уже подключённый `onnxruntime-web`. Модели входят в MSI (+~15 МБ), сеть не нужна. Слой сборки текста и UI общие с Android.

## 7. План по частям

1. Каркас: иконка на экране заметок, оверлей сканера, переходы, i18n, JS-адаптер OCR с заглушкой. Тесты `layout.js` на синтетических боксах.
2. Ввод: камера в WebView, галерея, системная камера, несколько страниц (лента миниатюр, удаление, перестановка).
3. Нативная часть: CMake, ncnn + opencv-mobile в CI, JNI: `detectQuad`, `warp`, `recognize`; мост в `MainActivity`; `/scan/` path handler.
4. Предобработка в UI: автоподбор рамки, ручная правка углов, поворот, кадрирование.
5. Сборка текста: порядок чтения (колонки), строки, абзацы, переносы, омоглифы.
6. Результат: редактируемый предпросмотр → новая заметка / вставка в открытую, экспорт TXT, «сохранить оригиналы» через `addImage()`.
7. NOTICE/лицензии в «О программе», `docs/`, бенчмарк-режим (время и пиковая память по стадиям, выводится в результат и копируется кнопкой).

## 8. Что нельзя проверить здесь и что понадобится от вас

Здесь нет Android SDK/NDK/adb и телефона. Здесь я проверю: `node --test` (сборка текста, адаптер, отсутствие сети в коде сканера), `npm run build` и UI в браузере на десктопе с заглушкой OCR. **Нативную часть проверит только CI-сборка APK.** Если её не запускать, сборку можно сделать в Android Studio.

На телефоне понадобится:
1. Поставить APK из CI-артефакта.
2. **Включить авиарежим** (Wi-Fi и данные выключены).
3. Отсканировать набор: русский, английский, смешанный текст, страница с поворотом 90°/180°, при слабом свете, документ на 5+ страниц.
4. В режиме бенчмарка скопировать отчёт (время детекции, распознавания и всего; пиковая память) и прислать его вместе с моделью телефона.
